# Как проверяется качество

## Эталон

Эталон снят с работающего прототипа: чистые функции посчитали признаки, векторы, коэффициенты модели, прогнозы и порядок выдачи. Тесты сверяют результаты ядра с эталоном:

- **допуск 1e-6** на числа — этого достаточно, чтобы поймать настоящую ошибку и не ловить шум плавающей точки;
- **порядок выдачи** сравнивается отдельно: при равных числах важно, кто первый;
- **случаи расхождения языков** проверяются явно: часовой пояс, стабильность сортировки, Unicode и классы пробелов ведут себя в Go и JavaScript по-разному, и эти места перечислены поимённо.

Эталон не считается истиной сам по себе: если тест расходится, есть три равноправных объяснения — дефект порта, осознанное отличие или кривое место прототипа, которое решено повторять. Каждое расхождение попадает в отчёт с классификацией.

## Синтетические фикстуры

На живых данных часть развилок не воспроизводится: значение в другом регистре, пробел внутри значения, пустая строка вместо числа, дубликат ключа внутри одного файла. Такие случаи описаны отдельными фикстурами — иначе при первом же рефакторинге их «упростили» бы обратно.

## Тесты

- Юнит-тесты на разбор полей, признаки, модель и похожесть; табличные случаи на границы.
- Тесты миграций: накат с нуля, идемпотентность, расширение ограничений.
- Проверка круга «импорт → база → вектор»: данные, прошедшие через базу, должны дать тот же вектор, что и данные в памяти.
- Свыше 100 тестов, линтер, CI на каждый коммит.

## Разработка с ИИ-агентом и проверки

- План и спецификация ревьюятся **до** кода.
- Отдельный агент пишет тесты по спецификации — не автор правки.
- По области изменения подключаются проверки: ревью кода, безопасность, тесты, сверка с эталоном, аудит контракта и зависимостей.
- В каждом отчёте агента есть раздел **«Не проверено»**: что осталось без подтверждения, каким способом это можно проверить и почему не проверено сейчас. Отчёт без этого раздела не принимается.
